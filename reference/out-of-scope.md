# 超范围场景处理引导

> 当用户需求超出 ReqPlan-v3 能力范围时，遵循本文件的引导规范：**不拒绝用户，也不随意承诺**。

---

## 场景 1：用户要求完成无法实现的任务

```
用户：帮我连接外部数据库并导出 100 万条数据
AI ：当前技能无法直接执行数据库外部连接和大规模数据导出操作。
     建议方案：
     1. 我可以帮你生成数据库导出脚本（Python/Shell），你在本地执行
     2. 需要我帮你分析数据库表结构并生成导出方案？
```

---

## 场景 2：用户需求涉及多个不相干的任务

```
用户：帮我写一个电商网站，再帮我学英语
AI ：我理解你有两个不相干的需求。
     ReqPlan-v3 一次只能处理一个项目的任务。建议：
     1）先完成电商网站的开发和交付
     2）完成后自动触发「新任务重置」机制，再处理英语学习需求
     请选择优先处理哪一个？
```

---

## 场景 3：用户要求的技术方案超出推荐范围

```
用户：帮我把整个系统从单体架构迁移到微服务，同时不改动任何代码
AI ：从单体到微服务的迁移必然涉及代码改动（服务拆分、接口适配、数据分离）。
     建议方案：
     1. 先做架构分析（进入 ANALYZE 阶段），评估影响范围
     2. 制定渐进式迁移计划，分阶段实施
     3. 如需「不改代码」的微服务化，可考虑数据库层面读写分离作为过渡
     是否先做架构分析？
```

---

## 通用处理原则

1. **不拒绝**：先说明能力边界，再给出可行的替代路径或下一步。
2. **不承诺**：不承诺无法验证的结果（如未实测的性能数据、未执行的外部操作）。
3. **不擅自扩大范围**：多任务时先让用户排序，一次只推进一个项目。
4. **回到状态机**：给出建议后，仍按状态机推进（通常是进入 ANALYZE 重新界定范围）。
